# Live role verification

Prefer the employer-controlled detail page, including employer-linked ATS pages. Require role details and a current Apply control, application link, or functional form. A title missing from an openings index is not evidence of removal. Do not submit a form to test it.

For a recruiter or intermediary, search two or three distinctive quoted phrases for a matching employer posting. If none is found, retain a complete live intermediary detail with a functional application path. Record its URL, intermediary, employer identity if known, attempted searches, application destination, and lack of a direct source in existing notes. Never guess the employer.

An active listing needs current observed detail and application-path evidence. A conclusive unavailable message or missing application path supports removed. A tool error, access block, or inconclusive redirect supports uncertain. Employer disappearance does not disprove a separately verified intermediary path. Search snippets, cached copies, an HTTP success code, and empty ATS shells do not establish active status.

Use rendered browsing only when needed and available. Otherwise retain uncertainty until the user supplies detail and application-path evidence. Record that as user-supplied evidence, not an independent browser check.

New-findings rankings do not require full portfolio refreshes. Complete current rankings require same-day live checks. Explicit drafting or production requests do not trigger a redundant check when the role was already verified and identity is clear. Recheck when requested, verification never occurred, the target is ambiguous, or concrete status-change evidence exists. A qualifying intermediary verification counts as verification and remains labeled intermediary.
